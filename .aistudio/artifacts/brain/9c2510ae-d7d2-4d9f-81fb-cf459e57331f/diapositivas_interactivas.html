DIAGNÓSTICO INSTITUCIONAL

EL PROBLEMA QUE RESOLVEMOS

¿Cómo se organizan los torneos escolares tradicionalmente?

❌ Planillas en Papel y Cuadernos

Inscripciones y marcadores en hojas que se rompen, manchan o traspapelan. Cero respaldo digital histórico.

❌ Choque de Canchas y Horarios

Dos grados citados a la misma hora en la Cancha Principal provocando discusiones y retrasos en el calendario.

❌ Desinformación en Estudiantes

Docentes saturados en los descansos con alumnos preguntando: "¿Profe a qué hora juego? ¿Quién ganó ayer?".

❌ Sobrecarga Administrativa

Más de 25 horas semanales gastadas armando llaves y cuadrantes manualmente en lugar de orientar la clase.

💡 Impacto: Afecta a más de 800 estudiantes y 40 equipos en 5 disciplinas deportivas.
PROPUESTA DE VALOR

LA SOLUCIÓN: INTERCURSOS CHINCÁ

Ecosistema web integral con doble experiencia de usuario

⚙️ Panel de Administración

  • Inscripción inmediata por deportes (Fútbol, Baloncesto, Voleibol, Atletismo, Microfútbol).
  • Motor estricto anti-conflictos que bloquea colisiones de canchas.
  • Mesa de control para editar marcadores y estados (Programado, En Juego, Finalizado).

👁️ Vista Visitante / Estudiantes

  • Consulta pública en vivo sin necesidad de crear usuario ni contraseña.
  • Atajos rápidos de un solo toque para cada grado escolar.
  • Filtros cruzados por deporte, cancha asignada y estado del partido.
⚡ 100% digital, accesible en cualquier celular, tablet o computador.
INGENIERÍA Y ESTRUCTURA

MODELO DE DATOS Y ARQUITECTURA

Esquema relacional en Supabase / PostgreSQL

Tablas Principales:

📂 deportes: id, nombre, icono, lugar_default
📂 lugares: Cancha Principal, Cubierta, Coliseo, etc.
📂 equipos: id, nombre, deporte_id (relación N:1)
📂 partidos: equipo_local, equipo_visitante, lugar, fecha_hora, fase, marcadores, estado, ganador
// types.ts - Tipado Estricto con TypeScript
export interface Partido {
  id: string;
  deporte_id: SportKey;
  equipo_local: string;
  equipo_visitante: string;
  lugar: string;
  fecha_hora: string;
  estado: 'Programado' | 'En Juego' | 'Finalizado';
}
🛡️ Tipado estricto que previene errores de ejecución y asegura integridad referencial.
EL CORAZÓN DEL CÓDIGO

ALGORITMO ANTI-COLISIONES

Cómo el código soluciona el problema de los choques de cancha

// src/context/TournamentContext.tsx - Validación de disponibilidad
const programarPartido = (nuevo: Partido) => {
// Comprobar si la cancha ya está reservada en esa fecha y hora
const conflicto = partidos.find(p =>
p.lugar === nuevo.lugar && p.fecha_hora === nuevo.fecha_hora
);

if (conflicto) {
return {
ok: false,
mensaje: `⚠️ Conflicto: "${nuevo.lugar}" ya tiene programado el partido "${conflicto.equipo_local} vs ${conflicto.equipo_visitante}" en ese horario.`
};
}
// Si no hay conflicto, se registra con éxito
setPartidos(prev => [nuevo, ...prev]);
};
✅ Garantía lógica: Ningún partido se puede programar en el mismo escenario al mismo tiempo.
